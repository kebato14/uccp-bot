# Запуск бота на сервере 24/7

Цель: бот работает круглосуточно, не зависит ни от чьего компьютера,
сам поднимается после перезагрузки сервера и после сбоя.

## 1. Подготовка (один раз)

```bash
sudo adduser --system --group --home /opt/uccp-bot uccp
sudo apt update && sudo apt install -y python3.12 python3.12-venv git
sudo -u uccp git clone https://github.com/kebato14/uccp-bot.git /opt/uccp-bot
cd /opt/uccp-bot
sudo -u uccp python3.12 -m venv .venv
sudo -u uccp .venv/bin/pip install -r requirements.txt
```

Проверьте версию: нужен **Python 3.11 или новее**. На 3.9 не работает uvloop
и часть ускорений.

## 2. Настройки

```bash
sudo -u uccp cp .env.example .env
sudo -u uccp nano .env
```

Обязательно: `BOT_TOKEN`, `BOOTSTRAP_ADMIN_IDS`.
Для сервера рекомендуется `LOG_LEVEL=WARNING`.

Перенесите базу со старого места, если она уже наработана:

```bash
sudo -u uccp cp /путь/к/старой/uccp.db /opt/uccp-bot/uccp.db
```

## 3. Служба systemd

```bash
sudo cp deploy/uccp-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now uccp-bot
systemctl status uccp-bot
```

Теперь бот стартует автоматически при загрузке сервера и перезапускается
через 5 секунд после любого сбоя.

## 4. Проверка

```bash
journalctl -u uccp-bot -n 30 --no-pager
```

В логе должна быть строка вида
`Бот запущен: @имя | python 3.12.x | uvloop: да`.

В самом боте отправьте `/ping`, затем поработайте 10–15 минут и отправьте
`/perf` — команда покажет реальную скорость по этапам.

## 5. Обновление

```bash
cd /opt/uccp-bot
sudo -u uccp git pull
sudo -u uccp .venv/bin/pip install -r requirements.txt
sudo systemctl restart uccp-bot
```

Миграции базы применяются при старте автоматически.

## ⚠️ Одновременно должен работать только ОДИН бот

Два процесса с одним токеном делят обновления между собой: половина нажатий
остаётся без ответа, и это выглядит как сильные тормоза. Бот теперь сам
не даёт запустить второй экземпляр на том же компьютере, но на **разных**
машинах эту ситуацию проверить нельзя.

Поэтому: после переноса на сервер бот на личном компьютере нужно остановить
и больше не запускать.

```bash
pkill -f uccp_bot.bot     # на компьютере, где он запускался раньше
```

Признак проблемы в логах: `Conflict: terminated by other getUpdates request`.

## 6. Если сервер далеко от Telegram

Задержки могут быть в канале связи, а не в боте — `/perf` это покажет.
Варианты:

* сервер в Европе (Telegram обслуживает регион из Амстердама);
* прокси до Telegram: `TELEGRAM_PROXY=http://user:pass@host:port` в `.env`.

## 7. Резервные копии

Копия базы делается ежедневно в 03:20 и приходит администраторам в Telegram.
На сервере дополнительно проверьте, что папка `/opt/uccp-bot/backups`
доступна на запись пользователю `uccp`.
