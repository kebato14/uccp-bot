# Бот заявок УЦЦП — Hotdogger / Moose Café

Telegram-бот для создания, распределения, контроля и закрытия технических
и хозяйственных заявок по торговым точкам.

Цепочка: **Заявка → Назначение исполнителя → Выполнение → Фото результата →
Стоимость → Подтверждение → Закрытие → История → Автоматический ежемесячный
отчёт УЦЦП в Google Sheets.**

Главное правило: отсутствие исполнителя, группы или регистрации мастера
**никогда** не приводит к потере заявки — она уходит администратору бота.

---

## Быстрый старт

```bash
/opt/homebrew/bin/python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env        # указать BOT_TOKEN
.venv/bin/python -m uccp_bot.bot
```

При первом запуске создаётся база `uccp.db` и наполняются справочники:
бренды, торговые точки, общие объекты, 7 категорий и мастера из ТЗ.

### Первый администратор

Роль себе никто назначить не может, поэтому первый администратор задаётся в `.env`:

1. Отправьте боту `/id` — он покажет ваш Telegram ID.
2. Впишите его: `BOOTSTRAP_ADMIN_IDS=123456789` и перезапустите бота.

Дальше все роли выдаёт администратор через панель бота.

## Доступ и роли

**Главный принцип: никто не назначает себе роль сам.** Пользователь сообщает
только сведения о себе, администратор проверяет человека и выдаёт права.

### Как человек получает доступ

1. `/start` → имя → фамилия → должность (своими словами) → бренд → точка.
2. Бот: «Заявка на регистрацию отправлена администратору. Ожидайте подтверждения».
   До подтверждения рабочий функционал закрыт полностью.
3. Администратору приходит карточка заявки с кнопками ✅ Подтвердить / ❌ Отклонить.
4. При подтверждении администратор назначает роль, бренд, точку, а мастеру —
   направления работы.
5. Пользователь получает уведомление «Регистрация подтверждена. Ваша роль: …»
   и рабочее меню. Мастеру: «Теперь вы будете получать назначенные вам заявки».

При отклонении указывается причина — пользователь её видит и может подать заявку заново.

### Роли

| Роль | Что видит и может |
|---|---|
| **Сотрудник / менеджер точки** | создаёт заявки, видит только свои |
| **Администратор точки** | все заявки своей точки: актуальные, приоритетные, просроченные, выполненные |
| **Операционный директор** | все заявки своего бренда (Moose Café **или** Hotdogger), отчёты по бренду |
| **Мастер / исполнитель** | только назначенные ему заявки |
| **Администратор системы** | полный доступ, подтверждает регистрации, назначает роли |

Область доступа действует везде: в списках, в карточке заявки, в отчётах
и в выгрузке Excel — отчёт администратора точки содержит только его точку,
отчёт операционного директора — только его бренд.

### Раздел «Пользователи»

⚙️ Администрирование → 👥 Пользователи и роли. В карточке человека можно
в любой момент: сменить роль, бренд, точку, направления мастера, указать телефон,
**временно заблокировать** доступ или **отключить полностью** (и вернуть обратно).
Пользователь сразу получает уведомление об изменении.

## Объекты

Заявки оформляются по трём группам объектов:

| Группа | Объекты |
|---|---|
| **Hotdogger** | 82-мк, Сема мол, Куруши Кабир, Созидание, Аэропорт |
| **Moose Café** | TCell, Opera, 92 мк, Кохи Вахдат, Зайнаб Мол |
| **Общие объекты** | Офис, Центральный склад Зайнаб Мол, Цех Пекарня, Цех Кондитерский |

Общие объекты не относятся ни к одному бренду, но заявки по ним — и технические,
и организационные — оформляются так же. Мастер, привязанный к обоим брендам,
обслуживает и общие объекты автоматически; привязанный к одному бренду — нет,
такая заявка уйдёт администратору.

В отчётах общие объекты идут отдельной строкой, не смешиваясь с расходами
по брендам. Сотрудника офиса или склада можно зарегистрировать на конкретный
объект — тогда он видит заявки только по нему.

Добавлять, переименовывать и отключать объекты можно в боте:
⚙️ Администрирование → 🏬 Торговые точки.

## Мастера на фиксированной оплате

Часть мастеров работает не по каждой заявке, а по **фиксированной ежемесячной
оплате** — например, обслуживание кофемашин. Для них закрытие заявки короче:

| Обычный мастер | Мастер на фиксированной оплате |
|---|---|
| 1. что сделано | 1. какие работы проведены |
| 2. фото результата — **обязательно** | 2. фото — **по желанию** |
| 3. стоимость работ | — |
| 4. стоимость материалов | — |

Бот вообще не спрашивает у такого мастера деньги. Заявка попадает в историю
обслуживания оборудования и в контроль выполненных работ, но **не формирует
сумму к оплате**: в карточке вместо стоимости стоит пометка «входит в
фиксированную месячную оплату», в отчётах такие заявки считаются отдельной
строкой и не входят в расходы, в Excel и Google Sheets в колонках стоимости —
«фикс. оплата».

**Как включить:** ⚙️ Администрирование → 👥 Пользователи → мастер →
💰 **Оплата: фиксированная за месяц**. Мастер получит уведомление об изменении
условий. Переключается в обе стороны в любой момент.

Отметка проставляется на заявке **в момент выполнения**, поэтому смена условий
мастера не переписывает историю уже закрытых заявок.

Для маршрутизации добавлена категория **☕️ Кофемашины** — заявки по ним идут
профильному мастеру, а не общему мастеру по оборудованию.

## Модуль организационных заявок УЦЦП

Организационные задачи хранятся **отдельно** от технических и ремонтных:
своя таблица в БД (`org_requests`), своя нумерация `ORG-2026-000001`, свои
статусы и своя статистика. Смешивания нет нигде — ни в списках, ни в отчётах,
ни в выгрузках.

**Структура:** заявка → точка/объект → описание задачи → срок → автор →
ответственный → статус. Автор подставляется из профиля автоматически.

**Путь:** 🗂 Заявки УЦЦП → ➕ Новая заявка УЦЦП → объект (торговая точка
из справочника или произвольный: офис, склад, цех) → описание → приоритет →
срок → ответственный.

**Цикл:** Новая → В работе → Выполнена → Закрыта. Ответственный берёт задачу
в работу и отмечает выполнение с описанием результата и затратами; закрывает
её автор или администратор — ответственный сам себя закрыть не может.
Есть возврат на доработку, комментарии, смена ответственного, отмена,
журнал действий и автоматическая отметка просрочки.

**Кто ставит задачи:** администратор точки, операционный директор и
администратор системы. Ответственным можно назначить любого пользователя
с доступом. Видимость — по тем же правилам ролей, что и в ремонтных заявках.

**Отчёты.** 📊 Отчёты → выбор модуля:

| Модуль | Кому доступен |
|---|---|
| 🔧 Технические и ремонтные | всем, у кого есть отчёты |
| 🗂 Организационные УЦЦП | всем, у кого есть отчёты |
| 📋 Сводный отчёт по обоим модулям | только администратору системы |

Сводный отчёт показывает два модуля отдельными блоками плюс общий итог —
статистика по-прежнему ведётся раздельно. Excel сводного отчёта содержит
два листа: «Ремонтные» и «Организационные».

В Google Sheets месячная выгрузка создаёт два листа: `ГГГГ-ММ` (ремонтные)
и `ГГГГ-ММ-УЦЦП` (организационные).

## Резервное копирование

База `uccp.db` — единственное место, где живут пользователи, заявки, история
и стоимости; в репозиторий она намеренно не попадает. Поэтому копия делается
автоматически **каждый день в 03:20** сразу в три места:

| Куда | Когда работает |
|---|---|
| папка `backups/` на компьютере | всегда, хранятся последние 14 копий |
| личные сообщения администраторам | всегда — файл можно скачать на телефон |
| папка на Google Диске рядом с отчётами | когда настроен доступ к Google |

Копия снимается средствами SQLite (`Connection.backup`), поэтому её можно
делать на работающем боте — приём заявок не останавливается, файл не бьётся.

**Сделать копию прямо сейчас:** ⚙️ Администрирование → 💾 Резервная копия.
Бот пришлёт файл в чат.

**Восстановление:** остановите бота, положите файл копии на место `uccp.db`
и запустите снова — всё содержимое вернётся, включая пользователей и историю.

Настройки в `.env`: `BACKUP_HOUR`, `BACKUP_KEEP`, `BACKUP_TO_TELEGRAM`.

## Google Sheets — ежемесячный отчёт

В начале каждого месяца (по умолчанию 1-го числа в 01:10) бот формирует отчёт
за прошедший месяц и записывает его в Google-таблицу отдельным листом `ГГГГ-ММ`.
Администраторы и операционный директор получают ссылку в Telegram.

**Что в листе:**

* детализация по каждой заявке — номер, дата, бренд, точка, категория, описание,
  исполнитель, приоритет, срок, статус, дата выполнения, дата закрытия,
  стоимость работ, стоимость материалов, итого, отметка просрочки;
* сводка — всего заявок, выполнено и закрыто, не закрыто, просрочено, отменено,
  общая сумма расходов и средняя стоимость заявки;
* расходы по брендам (Moose Café и Hotdogger), по каждой торговой точке,
  по каждому исполнителю и по категориям.

Лист месяца перезаписывается при повторной выгрузке — дублей не возникает.

### Как подключить (10 минут, один раз)

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/) и создайте проект.
2. В разделе **APIs & Services → Library** включите **Google Sheets API**
   и **Google Drive API**.
3. **APIs & Services → Credentials → Create credentials → Service account** —
   создайте сервисный аккаунт.
4. Откройте его → вкладка **Keys → Add key → Create new key → JSON**. Файл скачается.
5. Положите файл в папку проекта под именем `google_credentials.json`.
6. В `.env` укажите свою почту: `GOOGLE_SHARE_EMAIL=ваш@gmail.com` —
   бот сам создаст таблицу «Отчёты УЦЦП» и откроет вам доступ.
   Если таблица уже есть: откройте к ней доступ (роль «Редактор») для адреса
   `client_email` из JSON-файла и впишите её ID в `GOOGLE_SHEET_ID`
   (ID — часть ссылки между `/d/` и `/edit`).
7. Перезапустите бота.

Проверить вручную: в боте 📊 **Отчёты** → **📤 Месячный отчёт в Google Sheets**,
либо команда `/gsheets`.

Пока ключ не подложен, ничего не ломается: в конце месяца бот пришлёт тот же
отчёт файлом Excel и напомнит о настройке.

## Структура

```
uccp_bot/
  bot.py              запуск и сборка диспетчера
  config.py           настройки из .env
  db/models.py        Users, Roles, Brands, Outlets, Categories, Executors,
                      Requests, RequestStatusHistory, Comments, Attachments,
                      Costs, TelegramGroups, Equipment
  db/seed.py          справочники и исполнители из ТЗ
  handlers/           start (регистрация), approval (подтверждение доступа),
                      create, lists, actions, org (заявки УЦЦП), admin,
                      reports, help, groups
  keyboards/          меню, календарь, кнопки заявки

                      reports, excel, gsheets, numbering

```

## Исполнители из ТЗ (п.13)

| Направление | Мастер | Бренды |
|---|---|---|
| Сантехника | Асрор | оба |
| Обслуживание оборудования | Алишер | оба |
| Электрика | Назрулло | оба |

Телефоны и Telegram-аккаунты мастеров в репозитории не хранятся — их вносит
администратор в боте (⚙️ Администрирование → 👥 Пользователи). Личные данные
сотрудников остаются только в рабочей базе.

Вентиляция, ремонт/мебель, IT и «Другое» исполнителей пока не имеют —
такие заявки по правилам п.14 уходят администратору.

Мастера заведены без Telegram ID и контактов. Пока мастер не нажал `/start`, бот пишет
администратору: «Исполнитель ещё не зарегистрирован в боте. Личное уведомление
не отправлено. Заявка передана администратору для контроля». Как только мастер
запустит бота (по @username узнаётся автоматически), заявки начнут приходить
ему в личные сообщения.

## Работа в группах

Добавьте бота в рабочую группу и привяжите направление:

```
/bind электрика
```

Бот отвечает только когда видит описание проблемы, не чаще одного раза
в 10 минут на группу, и подсказывает, каких данных не хватает.
